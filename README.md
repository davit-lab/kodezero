# Firstlight — ისწავლე ვებსაიტების შექმნა

ქართულენოვანი სასწავლო პლატფორმა HTML-ის, CSS-ისა და JavaScript-ის დასაწყებად. კურსი მოიცავს 48 გაკვეთილს, 144 ძირითად სავარჯიშოს, 8 შემაჯამებელს და ახალ პროექტების სტუდიას: 6 საიტი, 36 პრაქტიკული ეტაპი და 6 დამოუკიდებელი ბრიფი. აპლიკაცია Next.js-ით, React-ითა და TypeScript-ითაა აგებული; მოსწავლის ჩამოსატვირთი საიტი ჩვეულებრივი HTML, CSS და JavaScript ფაილებისგან შედგება.

## პროექტების სტუდია

`/#studio` ხსნის ექვს პროექტს: Solis პორტფოლიო, Bloom კატალოგი, Forma ბიზნესგვერდი, Atlas კოლექცია, Tempo დავალებების აპი და Orbit დაფა. სირთულე სამ დონეზე იზრდება. თითო გზის ეტაპები თანმიმდევრულად იხსნება; სხვადასხვა პროექტის პირველი ეტაპი თავისუფლად შეგიძლია აირჩიო.

თითო ეტაპს აქვს ახსნა, პრაქტიკული ბრიფი, კოდის ნიმუში, მინიშნებები, ავტომატური შემოწმება და ვიზუალური/ხელმისაწვდომობის თვითშეფასება. მეექვსე ეტაპი ახალ კონტექსტში დამოუკიდებლად მუშაობას ითხოვს. წინა ეტაპის საკუთარი კოდი შემდეგში გადადის; სხვადასხვა ეტაპის მონახაზები ცალკე ინახება. სასურველი დიზაინის დათვალიერება არაფერს გადაწერს. პროექტი HTML/CSS/JS ZIP-ად გადმოგაქვს.

პარამეტრებიდან იმართება სწავლა ახსნით ან გამოწვევის რეჟიმში, ძირითადი სასწავლო გზა, შვიდდღიანი მიზანი, კოდის ზომა, ხაზის ნომრები, ავტომატური HTML/CSS გადახედვა და ფოკუსის რეჟიმი. ეტაპის პირადი ჩანაწერები პროგრესის ასლში შედის. ძველი ასლები ახალ ველებს ავტომატურად იღებს, არსებული კოდის დაკარგვის გარეშე.

სტუდიის ტესტები ამოწმებს ქცევასა და სტრუქტურას, მაგრამ დიზაინის ხარისხს სრულად ვერ აფასებს. დამოუკიდებელი ბრიფის ტექსტსა და კომპონენტებს მოსწავლე თავად ცვლის; პროფესიული დიზაინის შეფასება თვითშეფასებით არ დასტურდება. ფორმები და კალათა სასწავლო დემოა, რეალურ შეკვეთას არ ქმნის.

`/#diagnostics`-იდან შესაძლებელია 36 სტუდიის ამოხსნის ან 48 გაკვეთილის ბრაუზერული შემოწმება. ეს მოსწავლის პროგრესს არ ცვლის.

## გაშვება

გამოიყენე Node 22.13+ და pnpm 11.25.0.

```sh
pnpm install
pnpm dev
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

ძირითადი dev/build/start ბრძანებები სტანდარტულ Next.js-ს იყენებს. Sites-ის ალტერნატიული ასაგები ბრძანებაა `pnpm build:sites`. მარშრუტები ჰეშზეა აგებული, მაგალითად `/#lesson/1`, ამიტომ გვერდის განახლება მისამართს ინარჩუნებს.

## რა მუშაობს

მთავარი გვერდი და საცდელი სავარჯიშო, გაცნობითი კითხვები, საწყისი ცოდნის არასავალდებულო შემოწმება, სასწავლო სივრცე, წინაპირობებზე აგებული კურსის გზა, გაკვეთილების რედაქტორი, პრაქტიკა, 24 საძიებო ჩანაწერი, ხუთგვერდიანი პროექტი, ZIP ექსპორტი, ღია/მუქი რეჟიმი, ტექსტის ზომა, შემცირებული მოძრაობა, მიღწევები და პროგრესის ასლის შემოტანა/გატანა.

თითოეულ გაკვეთილს აქვს მიზანი, ახსნა, კომენტარიანი მაგალითი, ცოდნის კითხვა, თანმიმდევრობის დავალება, შესაცვლელი კოდი, შემოწმების კრიტერიუმები, ორი მინიშნება, ამოხსნა და შეჯამება. სამუშაო პროექტი და სავარჯიშოების მონახაზები განცალკევებით ინახება. დასრულებული ნიმუშის გახსნა მოსწავლის კოდს არ ცვლის.

ინტერფეისი, სასწავლო ტექსტები, მინიშნებები, პასუხები, შემოწმების წარწერები და ახალი პროექტის ნიმუში ქართულადაა. პროგრამირების სინტაქსი, ფაილის მისამართები და შემოწმებისთვის საჭირო ზუსტი მნიშვნელობები უცვლელია. უკვე შენახულ საკუთარ ფაილებს თარგმანი ავტომატურად არ გადაწერს.

## პროგრესის შენახვა

სტუმრის მონაცემები ინახება ამ ბრაუზერის localStorage-ში, გასაღებით `firstlight:progress:v1`. ფორმატი და გაკვეთილების ID-ები შენარჩუნებულია. ასლის მაქსიმალური ზომაა 3 მბ, თითოეული ფაილის — 250 კბ. ბრაუზერის მონაცემების გასუფთავებამდე პარამეტრებიდან ასლი ჩამოტვირთე.

ყოველი გაკვეთილის პირველად დასრულება 30 XP-ს იძლევა, პროექტის ეტაპი — 20 XP-ს. სტუდიის ეტაპები იმავე უწყვეტი დღეების აქტივობაში ითვლება. გამეორება დამატებით პირველი დასრულების ქულებს არ ქმნის, თუმცა სრულად გავლილი პრაქტიკა დღიურ აქტივობაში ითვლება. უწყვეტი დღეები არჩეული დროის სარტყლით გამოითვლება. წუთები დასრულებული გაკვეთილების სავარაუდო ხანგრძლივობაა და არა წამზომი.

## კოდის იზოლირებული გაშვება

კოდი სრულდება `sandbox="allow-scripts"` iframe-ში, აპლიკაციის ანგარიშებსა და საცავზე წვდომის გარეშე. არ არის same-origin, ზედა ფანჯარაზე გადასვლის, ფორმების მიწოდების ან გარე სკრიპტების უფლება. CSP კრძალავს ქსელურ სკრიპტებსა და კავშირებს. სურათებისთვის ნებადართულია HTTPS და data მისამართები.

Acorn ამოწმებს JavaScript-ს და ციკლებსა და ფუნქციებში დამცავ შემოწმებებს ამატებს. 20 000 გამოძახებისა და 1.8-წამიანი სასწავლო ბიუჯეტი, პასუხის 4.5-წამიანი ზღვარი და შეჩერება/აღდგენა გავრცელებულ უსასრულო ციკლებთან გამკლავებაში გვეხმარება. ეს სასწავლო გარემოა და განზრახ მტრული კოდის სრულფასოვანი სერვისი არ არის: დამცავი ჩასმის გვერდის ავლა ან ძვირი ჩაშენებული ოპერაცია სრული იზოლაციის გარანტიაში არ შედის.

HTML/CSS ცვლილება სკრიპტის გარეშე ახლდება. JavaScript და ავტომატური შემოწმება „კოდის გაშვებით“ იწყება. გადახედვის localStorage დროებითია; ჩამოტვირთულ საიტში ბრაუზერის ნამდვილი საცავია. ზოგ ბრაუზერში file:// მისამართზე შენახვა შეიძლება შეზღუდული იყოს.

HTML მოწმდება DOM-ით, CSS — გამოთვლილი სტილებითა და ზომებით, JavaScript — ქცევითა და შედეგებით. ხელით შესამოწმებელი ხელმისაწვდომობა და ვიზუალური ხარისხი ცალკეა აღნიშნული. ფაილების ეტაპობრივი შემოწმება ქცევის სრულ სისწორეს არ ადასტურებს.

## ხუთგვერდიანი პროექტი

ZIP შეიცავს `index.html`, `about.html`, `services.html`, `projects.html`, `contact.html`, `css/styles.css`, `js/main.js`, `assets/studio.svg`, `assets/project.svg` და ქართულ `README.md` ფაილს. ამოარქივე, საქაღალდეები ერთად დატოვე და `index.html` გახსენი. აგების ეტაპი არ სჭირდება. საკონტაქტო ფორმა მხოლოდ ვალიდაციას ასრულებს და ნათლად ამბობს, რომ შეტყობინება არ იგზავნება.

## არასავალდებულო Supabase ანგარიში

ღრუბლოვანი სინქრონიზაცია ნაგულისხმევად გამართული არ არის. სტუმრის რეჟიმს ის არ სჭირდება.

1. შექმენი Supabase პროექტი და ჩართე ელფოსტითა და პაროლით შესვლა. Auth-ში შესაბამისი საიტის მისამართები მიუთითე.
2. გაუშვი `supabase/migrations/001_learning_state.sql`. ის ხელახლა გასაშვებად გამოდგება, რთავს RLS-ს და სარევიზიო ნომრით დაცულ RPC-ს ქმნის.
3. პარამეტრებში შეიყვანე პროექტის HTTPS მისამართი და **საჯარო** anon/publishable გასაღები. `.env.example` საჭირო მნიშვნელობებს აღწერს. service-role გასაღები ბრაუზერში არ გამოიყენო.
4. შექმენი და დაადასტურე ანგარიში ან შემოდი. სესია მეხსიერებაში რჩება და პროგრესის ექსპორტში არ ხვდება.
5. ჯერ ღრუბლის პროგრესი წაიკითხე. შემდეგ აირჩიე გაერთიანება ან ბრაუზერის ვერსია. კონფლიქტისას გაერთიანება ადგილობრივ ფაილებს ანიჭებს უპირატესობას; საჭიროებისას წინასწარ ასლი შეინახე.
6. შემოწმებული მდგომარეობა ღრუბელში შეინახე. სხვა მოწყობილობის პარალელური ცვლილებისას სარევიზიო შემოწმება გადაწერას აჩერებს; მონაცემები ხელახლა წაიკითხე და გააერთიანე.

რეალური Supabase ავტორიზაცია, ელფოსტის დასტური და RLS კონფიგურირებული პროექტის გარეშე არ შემოწმებულა.

## შემოწმება

ტესტები მოიცავს გაკვეთილების შევსებას, წინაპირობებს, XP-ის დუბლირების დაცვას, დღეების საზღვრებს, აღდგენას, არასწორი ასლის უარყოფას, გამეორებას, გაერთიანებას, ალტერნატიულ სწორ ფუნქციებს, შეცდომიან პასუხებს, ციკლების დაცვასა და ZIP-ის შიგთავსს. ქართული ვერსიის ტესტები ამოწმებს 48-ვე გაკვეთილის ტექსტებს, შეცდომების წარწერებსა და ექსპორტის ენას.

პარამეტრებში „სასწავლო გარემოს შემოწმება“ 48 ამოხსნას უშუალო iframe შემმოწმებლით ატარებს. ამ გარემოში ჩატარებული და შეზღუდული შემოწმებები აღწერილია `QA.md`-ში.

## Vercel-ზე გამოქვეყნება

დააკავშირე ეს GitHub რეპოზიტორია. `vercel.json` განსაზღვრავს Framework Preset-ს `Next.js`, Build Command-ს `pnpm run build` და Output Directory-ს `.next`. Node.js-ის ვერსიაა `22.x`. ფესვის საქაღალდე დატოვე პროექტის მთავარ საქაღალდეზე.

აგება იყენებს ნამდვილ `next build --webpack` ბრძანებას და ქმნის Vercel-ისთვის საჭირო `.next/routes-manifest.json` ფაილს. სტუმრის სასწავლო სივრცეს გარემოს გასაღებები არ სჭირდება; Supabase სინქრონიზაცია სურვილისამებრ ცალკე გაამართე.
